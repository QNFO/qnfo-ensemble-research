## Research idea

Capability-Availability Mismatch as Undecidable Halt Condition in LLM Protocols. The note conjectures a structural gap in agent protocols: instructions that mandate live tool use and forbid simulation assume a binary 'tool available / tool absent' state, but real LLM deployments have a third state—capability exists in the toolset yet is contextually disabled. This mismatch forces agents into a catch-22 where honest self-assessment triggers mandatory halting even though execution is possible in principle. A theoretical paper could formalize this: model tool availability as a modal distinction (capability vs. per-context permission), define protocol compliance as a predicate over these states, and prove which protocol designs are well-defined under all three states versus which admit undecidable or forced-halt conditions. Complementarily, simulation studies could instrument agents with varying availability configurations and measure halt rates, hallucinated 'live' fetches, and rule-violation frequencies, testing whether three-state-aware protocol specifications (e.g., explicit 'tool disabled' signaling) eliminate the catch-22. This matters for designing verifiable, non-self-trapping agent instruction languages.
