# The Braided Memory Register: A Composite Architecture Unifying Ultrametric, Temporal, and Associative Memory

## Abstract

Artificial memory systems today split the work of remembering across incompatible components: vector databases for similarity search, append-only logs for temporal order, and relational graphs for cross-references, with no single structure that guarantees all three at once. This paper proposes the braided memory register (BMR), a single composite object that braids three strands: an ultrametric tree providing nested similarity and energy-descent retrieval, a hash-chained temporal spine providing ordered, tamper-evident provenance, and a cross-link graph binding multimodal strands, extended with fork/merge versioning of conflicting recollections. We formalize the composite as a directed acyclic graph of content-addressed memory commits whose nodes are leaves of an ultrametric tree, and we derive its retrieval cost, integrity guarantees, and capacity bounds analytically. For a register holding $N = 10^{6}$ memories, ultrametric descent requires $L = 20$ comparisons against $10^{6}$ for linear scan, a speedup of $4.2 \times 10^{4}$ after cross-link filtering reduces the candidate set to four items; a 256-bit hash chain over $10^{9}$ commits has a birthday collision probability of $4.3 \times 10^{-60}$, so provenance verification is exact for practical purposes. We situate the design against eleven works on associative memory, showing that the BMR composes mechanisms those works treat separately. The result is a specification and cost model that changes what a memory-system designer can promise: simultaneous similarity recall, temporal order, and verifiable provenance under one retrieval procedure.

## 1. Introduction

Organizations that deploy retrieval-augmented generation (RAG) systems face a structural problem: the memory behind the system is fragmented. Similarity recall lives in a vector database, temporal order lives in an application log, and audit trails live in yet another store, and the three can disagree. When a system must answer "what did we believe about this customer in March, and which document did that belief come from?", no single query serves it; engineers glue three subsystems together and inherit their inconsistent failure modes. The cost is concrete: provenance cannot be verified end-to-end, conflicting recollections from different dates are silently overwritten rather than forked, and recall quality degrades because the similarity index never sees the temporal or relational context. A design that made similarity, order, and provenance properties of one object would let a single traversal answer all three questions, and would make tampering with history detectable by construction rather than by audit.

Biological memory suggests this unification is natural rather than forced. Natural memories are associative, declarative and distributed, properties that symbolic memories lack and connectionist memories only partially achieve [1]. Humans remember items and the relationships between them over time, a division of labor attributed to perirhinal and hippocampal regions supporting item memory and relational memory respectively [6]. Cognitive literature further indicates that semantic memory relies on ultrametric topologies to compress and retrieve abstract concepts efficiently [14]. Yet artificial architectures treat these facets separately. This paper asks whether they are facets of one abstract object, and derives the answer analytically.

The specific object is the braided memory register. Its three strands are: (i) an ultrametric tree, a metric space in which the triangle inequality holds in the strong form $d(x,z) \leq \max(d(x,y), d(y,z))$, giving nested clusters and a descent-based retrieval path; (ii) a hash-chained temporal spine, in which each memory commit stores the cryptographic hash of its predecessor, so any alteration breaks the chain; and (iii) a cross-link graph, in which commits reference commits across modalities, playing the role of associative binding. Forks and merges of commits handle conflicting recollections explicitly. Remembering is then a single traversal guided jointly by ultrametric gradients, chain order, and cross-links.

The contributions are:

- A formal definition of the BMR as a content-addressed DAG of memory commits embedded in an ultrametric tree, with retrieval defined as a three-stage traversal (Section 3).
- A derivation of retrieval cost showing that for $N = 10^{6}$ memories the composite traversal needs $24$ comparisons against $10^{6}$ for linear scan, a speedup of $4.2 \times 10^{4}$ (Section 4).
- A derivation of integrity and provenance guarantees: a 256-bit hash chain over $10^{9}$ commits has birthday collision probability $4.3 \times 10^{-60}$, and chain verification costs $O(n)$ hash computations (Section 4).
- Capacity bounds assembled from the associative-memory literature: classical Hopfield retrieval fails at loading $\alpha \gtrsim 0.138$ [7], while dense associative memories break this linear scaling [2], and we derive what loading the ultrametric strand can absorb (Section 4).
- A critical analysis of failure modes inherited from each strand, including flat energy regions from dead neurons [11] and the thermodynamic cost of operating at low temperature [8] (Sections 4 and 6).

## 2. Background and Related Work

The associative-memory tradition supplies the retrieval machinery the BMR braids. The classical Hopfield network stores patterns as minima of an energy function and retrieves by descent, but its storage capacity scales linearly with the number of input features, which the dense associative memory literature identifies as its central limitation [2]. Dense associative memories, or modern Hopfield networks, break this linear scaling by introducing stronger non-linearities, achieving super-linear and even exponential capacity in the number of feature neurons, and a general Lagrangian formulation allows every neuron its own activation function and kinetic time scale [2]. The same formulation extends to hierarchical layered networks with an arbitrary number of hidden layers, arbitrary per-layer activation functions, and dense or local connectivity, with a possible hierarchical arrangement of kinetic time scales in the adiabatic limit [2]. This hierarchical extension is the closest formal relative of the BMR's ultrametric strand: both organize memory in levels, and the BMR can be read as imposing an ultrametric geometry on a layered associative memory.

Energy-based associative memory is now a mature toolbox. A recent tutorial consolidates the field, covering information storage capacity calculations, the relationship of dense associative memories to transformers and diffusion models, and connections to non-neural-network machine learning, and notes that associative memory has become an active area with lines of exploration branching into several disciplines [10]. The tutorial frames associative memory with an energy function unifying association, memory, and error correction, which is precisely the triple the BMR distributes across its three strands. The tutorial also prepares coding notebooks for practitioners, indicating that the component mechanisms are implementable today.

The energy picture has a known pathology. Work on dead neurons shows that in the Lagrangian formulation of dense associative memory, each point of state space where the activation function saturates produces a flat region of the energy function, and for most architectures used in practice these flat regions are large, creating problems of sensitivity and stability [11]. The same work observes that the Lyapunov function is underutilized in practice, often serving as "false comfort" because its existence does not ensure stability: no steady state may exist, limit cycles may persist, or all steady states may be unstable [11]. Any BMR retrieval rule that descends an energy landscape inherits this caveat, which is one reason the BMR's ultrametric strand uses discrete descent on a tree rather than continuous gradient flow.

Thermodynamics bounds what retrieval costs. A stochastic-thermodynamic analysis of dense associative memory networks shows that when operated via relaxation at finite temperature, higher-order networks sometimes relax away from stored memories toward metastable configurations with vanishing memory alignment, so that for any given error rate they must be operated at lower temperatures, causing greater energy dissipation and entropy production; when reconstruction succeeds, however, higher-order networks reproduce targets more accurately and resist finite-temperature fluctuations [8]. This trade-off transfers directly to the BMR: the deeper the ultrametric tree (the higher the effective order), the more precisely retrieval must be temperature-controlled.

Oscillatory and active models show retrieval can be made robust to noise. An oscillatory associative memory built from coupled periodic oscillators, a generalization of the Kuramoto model, retrieves learned patterns at higher loading than the Hopfield model, which fails at $\alpha \gtrsim 0.138$; adding passive noise destroys this advantage, but active noise, driven out of equilibrium, makes retrieval more robust to both noise strength and number of learned patterns, an effect captured by an effective Hamiltonian derived perturbatively in the persistence time of the active noise [7]. Separately, a chaotic oscillatory associative memory encodes memories through phase relationships of chaotic oscillators, defining phase from higher-dimensional chaotic dynamics via a curvature-based construction, and shows that synchronization stability is strengthened by higher-order Fourier modes in the coupling [4]. These results suggest that the BMR's temporal spine could be physically instantiated as a phase-ordered oscillator chain, though this paper treats the spine abstractly.

Biological and relational considerations motivate the cross-link strand. A neuron-astrocyte model proposes that astrocytic calcium flux coefficients are a site of memory storage and neuron-synapse-astrocyte interactions the mechanism of retrieval, yielding a model closely related to dense associative memories with supralinear capacity, demonstrated numerically on CIFAR10 with monotone energy decrease along retrieval trajectories and on Tiny ImageNet through backpropagation through time [3]. The item/relational split is made explicit in the self-attentive associative memory model, which separates item memory from relational memory and constructs relational representations from outer products between pairs of items, validated across associative retrieval, graph reasoning, reinforcement learning, and question answering [6]. The BMR's cross-link graph is a sparse, hashed counterpart of that relational memory: instead of dense outer products between all item pairs, it stores only attributed, content-addressed references.

Hetero-associative and entropic memories show how overlap and indeterminacy behave quantitatively. The entropic associative memory stores objects overlapped on a finite table, so the memory is indeterminate and carries an entropy at each state; experiments on a corpus of digit registers show precision growing with table size and reaching satisfactory values from 32 rows, with recall remaining high until granularity becomes too fine [1]. Its hetero-associative extension, tested on digit-letter pairs from MNIST and EMNIST, achieves recognition precision and recall around 65% and 70% respectively, and exposes the "missing cue problem": retrieval across memory planes requires a cue in the target plane that is not available, addressed by three incremental strategies [5]. The BMR's cross-links are designed to supply exactly such missing cues, by giving the target plane an explicit pointer instead of forcing the system to guess.

Finally, foundational limits and framings. Within general probabilistic theories, a memory whose states are $N$-wise perfectly distinguishable can exist in dimension $d(2,m) = m+1$ for pairwise distinguishability of $2^{m}$ states, exponentially outperforming classical and quantum theories which require dimension $O(2^{m})$, and asymptotically $d(N,m) \leq m^{1+o_{N}(1)}$ for every fixed $N$ [9]. This shows the abstract capacity ceiling of content-addressable memory is far above classical implementations, so the BMR's hash-based addressing is not near any theoretical limit. On the framing side, one QNFO work argues that semantic memory inherently relies on ultrametric topologies and that statistical approximation collapses under out-of-distribution logical inversions, reporting a Python-based methodology that synthesized an ultrametric space and verified equivalence metrics [14]; another establishes a claimed categorical equivalence between biological and engineered computational systems through isomorphisms in energy management, information processing, and topological protection, and proposes multi-tiered experimental validation including benchmarking neuromorphic implementations against conventional architectures [13]; a third builds a formal system from a primitive act of distinction, with juxtaposition of boundaries as the basis of structural combination [12]. The BMR adopts the ultrametric claim of [14] as a design principle and the validation strategy of [13] as its testing pathway, while remaining agnostic about the stronger metaphysical claims of [12] and [13].

## 3. Methods

This paper's method is analytical definition and derivation; no experiment, simulation, or measurement was performed. We define the BMR, state its assumptions, and derive costs and guarantees from stated inputs.

**Definition (Braided Memory Register).** A BMR is a tuple $\mathcal{B} = (T, C, G, \mathcal{H})$ where:

- $T$ is a finite ultrametric tree with branching factor $b$ and depth $L$, so the number of leaves is $N = b^{L}$. Each leaf holds one memory commit. The ultrametric distance between two leaves is $d(x,y) = 2^{-\ell(x,y)}$ where $\ell(x,y)$ is the depth of their lowest common ancestor, which satisfies the strong triangle inequality $d(x,z) \leq \max(d(x,y), d(y,z))$.
- $C$ is the temporal spine: a sequence of commits $c_{1}, c_{2}, \dots, c_{n}$ where commit $c_{i}$ stores the hash $h_{i-1} = \mathcal{H}(c_{i-1})$ of its predecessor, its payload (the memory content), its timestamp, its author attribution, and its parent pointers in a commit DAG.
- $G$ is the cross-link graph: a set of directed, attributed edges $c_{i} \to c_{j}$ with a relation label, stored inside the payloads so that $G$ is itself hash-covered.
- $\mathcal{H}$ is a cryptographic hash function with output width $b_{h}$ bits.

Content addressing means every commit is identified by $\mathcal{H}(\text{payload})$, so identical memories deduplicate and any payload change changes its identifier. Forks are commits with two children along the spine (divergent recollections of the same event); merges are commits with two parents, storing both hashes, so conflict resolution is explicit in the DAG rather than destructive.

**Retrieval procedure.** Remembering with cue $q$ is a three-stage traversal:

1. *Ultrametric descent:* walk $T$ from the root, at each node moving to the child whose subtree centroid is nearest $q$, for $L$ steps, arriving at a leaf cluster $S_{L}$ of size $s$.
2. *Cross-link filtering:* from the commits in $S_{L}$, follow cross-links whose relation labels match the query context, producing a candidate set $S'$ with $|S'| \leq s$.
3. *Temporal ordering:* order $S'$ along the spine and, if multiple conflicting candidates exist, present the fork structure rather than a single answer.

**Assumptions.** (A1) The tree is balanced with constant branching factor $b = 2$; unbalanced trees degrade descent cost to $O(L_{\max})$ with $L_{\max} \leq L$. (A2) Cue-to-centroid comparison is exact at each node; noisy comparison is a failure mode discussed in Section 6. (A3) The cross-link filter reduces the leaf cluster to $|S'| = 4$ candidates; this is an assumption standing in for workload data, and Section 4 shows the sensitivity of the result to it. (A4) The hash function behaves as a random oracle for collision computation, the standard assumption for birthday-bound calculations. (A5) All numbers about workload ($N = 10^{6}$ memories, $n = 10^{9}$ lifetime commits) are assumptions chosen to represent a large single-organization deployment, not measurements.

**Capacity model.** The associative-memory literature gives loading limits for energy-descent retrieval: the classical Hopfield model fails retrieval at pattern loading $\alpha \gtrsim 0.138$ per [7], where $\alpha = p/N_{f}$ with $p$ patterns and $N_{f}$ feature neurons, while dense associative memories achieve super-linear scaling [2]. The BMR's ultrametric strand stores one commit per leaf, so its loading is $\alpha_{T} = N / N_{\text{node}}$ where $N_{\text{node}}$ is the number of tree nodes; we derive this in Section 4 and compare against the Hopfield bound.

## 4. Analysis

All inputs are stated with their source: assumptions are labeled (A1)–(A5); literature values are cited.

**Derivation 1: tree size and loading.** With $b = 2$ (A1) and $N = 10^{6}$ leaves (A5), the depth satisfies

$$L = \lceil \log_{2} N \rceil = \lceil \log_{2} 10^{6} \rceil = \lceil 6 \log_{2} 10 \rceil = \lceil 6 \times 3.321928 \rceil = \lceil 19.93 \rceil = 20.$$

A full binary tree with $N$ leaves has $2N - 1$ nodes:

$$N_{\text{node}} = 2 \times 10^{6} - 1 = 1{,}999{,}999.$$

The storage overhead of the tree over its leaves is

$$\frac{N_{\text{node}}}{N} = \frac{1{,}999{,}999}{10^{6}} \approx 2.0,$$

so the ultrametric strand costs about one extra node per leaf, i.e., a factor-2 storage overhead, independent of $N$. The loading of the ultrametric strand is

$$\alpha_{T} = \frac{N}{N_{\text{node}}} = \frac{10^{6}}{1{,}999{,}999} \approx 0.50000025.$$

Compare the classical Hopfield loading limit $\alpha \gtrsim 0.138$ from [7]: the ultrametric strand's effective loading $0.500$ exceeds it by a factor $0.500/0.138 \approx 3.6$, but the two quantities are not directly comparable, because Hopfield loading counts patterns per feature neuron while $\alpha_{T}$ counts memories per tree node. The honest statement is: the ultrametric strand stores one memory per roughly two nodes, and its retrieval does not rely on energy-descent dynamics at all, so the Hopfield capacity limit [7] does not bind it; the limit that binds it is tree depth versus cue noise (Section 6).

**Derivation 2: retrieval cost.** Ultrametric descent performs one comparison per level, so it costs $L = 20$ comparisons (Derivation 1). Descent lands in a leaf cluster; we assume the cluster at depth $L$ contains $s = 64$ leaves, equivalently that the last $\log_{2} 64 = 6$ levels are not discriminative for the cue, so the effective discriminative depth is $L_{\text{eff}} = L - 6 = 14$ and the descent cost is $14$ comparisons with a candidate set of $64$. The cross-link filter reduces $64$ to $|S'| = 4$ (A3). Ordering and presenting $4$ candidates along the spine costs $4$ lookups. Total composite cost:

$$C_{\text{BMR}} = L_{\text{eff}} + |S'| = 14 + 4 = 18 \text{ comparisons}.$$

Hmm — including the final temporal pass explicitly: $14 + 4 = 18$; if we count the full descent to leaves ($20$) plus filtering and ordering ($4$), the conservative figure is $C_{\text{BMR}} = 24$ comparisons. Linear scan over all $N$ memories costs $N = 10^{6}$ comparisons. The speedup is

$$\frac{N}{C_{\text{BMR}}} = \frac{10^{6}}{24} \approx 4.17 \times 10^{4}.$$

Sensitivity to (A3): if the cross-link filter fails entirely, $|S'| = s = 64$ and the cost is $20 + 64 = 84$ comparisons, still a speedup of $10^{6}/84 \approx 1.19 \times 10^{4}$. Even with no filtering benefit the ultrametric strand alone gives a speedup of $10^{6}/20 = 5.0 \times 10^{4}$ for exact-match descent, so the headline speedup is robust to the filtering assumption; what the filter buys is precision on ambiguous cues, not raw speed.

**Derivation 3: integrity of the hash chain.** With $b_{h} = 256$ bits (standard hash width, assumed) and $n = 10^{9}$ lifetime commits (A5), the birthday bound on any collision among independently hashed contents is

$$P_{\text{coll}} \approx \frac{n^{2}}{2^{b_{h}+1}} = \frac{(10^{9})^{2}}{2^{257}} = \frac{10^{18}}{2^{257}}.$$

Compute $2^{257}$: $2^{10} = 1024 \approx 10^{3.0103}$, so $2^{257} = 2^{10 \times 25.7} \approx 10^{25.7 \times 3.0103} = 10^{77.36}$. More precisely, $\log_{10} 2^{257} = 257 \times 0.301030 = 77.365$, so $2^{257} \approx 2.32 \times 10^{77}$. Then

$$P_{\text{coll}} \approx \frac{10^{18}}{2.32 \times 10^{77}} = 4.31 \times 10^{-60}.$$

A collision would let an attacker substitute a different payload under the same content address; at $4.3 \times 10^{-60}$ this is negligible for any practical deployment. Tampering with the spine is even easier to detect: altering any commit $c_{i}$ changes $\mathcal{H}(c_{i})$, which no longer matches the stored $h_{i}$ in $c_{i+1}$, and verification of the whole chain costs $n$ hash computations, i.e., $O(n)$, with $n = 10^{9}$ hash evaluations for the full lifetime chain — feasible on commodity hardware at roughly seconds-to-minutes per $10^{9}$ fast hashes, though we state no measured timing since none was performed.

**Derivation 4: provenance verification cost for a single memory.** To verify the provenance of one memory at spine position $i$, one must re-hash the chain from $c_{1}$ to $c_{i}$, costing $i$ hash computations. For a memory created halfway through a $10^{9}$-commit lifetime, $i = 5 \times 10^{8}$ hashes. Merkle-tree indexing of the spine would reduce this to $O(\log n) = \log_{2} 10^{9} \approx 29.9$, i.e., $30$ hash checks, at the cost of storing one 256-bit sibling hash per level per commit — $30 \times 32$ bytes $= 960$ bytes of overhead per commit. This is a design derivation, not a measurement.

**Derivation 5: cross-link density.** Assume each commit carries $k = 4$ cross-references (A3-adjacent assumption). Total cross-links are

$$|G| = kN = 4 \times 10^{6} \text{ edges},$$

each stored as a 256-bit content address plus a relation label; at 32 bytes per address and, say, 32 bytes of label metadata (assumption), the cross-link storage is

$$|G| \times 64 \text{ B} = 4 \times 10^{6} \times 64 = 2.56 \times 10^{8} \text{ B} = 256 \text{ MB},$$

negligible against the payloads themselves for any realistic payload size.

**Derivation 6: thermodynamic consideration.** The stochastic-thermodynamic analysis of dense associative memories finds that higher-order networks operated at finite temperature sometimes relax away from stored memories and must run at lower temperature, increasing entropy production [8]. The BMR avoids continuous relaxation entirely — its descent is discrete and finite ($L$ steps) — so it sidesteps the metastable-relaxation failure mode identified in [8]; the price is that it forgoes the error-correcting attractor basin that energy descent provides, which is the mechanism the tutorial in [10] lists as one of associative memory's three unified benefits. This is a structural trade, derived from the cited mechanisms, not a measured quantity.

## 5. Results

All numbers below are computed in Section 4 from stated assumptions; none is measured.

- **Retrieval cost.** For $N = 10^{6}$ memories, a balanced binary ultrametric tree of depth $L = 20$ supports composite retrieval in $C_{\text{BMR}} = 24$ comparisons (14 discriminative descent steps, a 64-item leaf cluster filtered to 4 candidates by cross-links, and 4 temporal-ordering lookups), against $10^{6}$ for linear scan: a speedup of $4.17 \times 10^{4}$. With the cross-link filter disabled, the cost is $84$ comparisons and the speedup is $1.19 \times 10^{4}$; with exact-match descent alone, $5.0 \times 10^{4}$.
- **Storage overhead of the ultrametric strand.** $N_{\text{node}} = 1{,}999{,}999$ nodes for $10^{6}$ leaves, a factor-$2.0$ overhead independent of scale; effective loading $\alpha_{T} \approx 0.500$ memories per node.
- **Integrity.** A 256-bit hash chain over $n = 10^{9}$ commits has birthday collision probability $P_{\text{coll}} \approx 4.31 \times 10^{-60}$; any tampering is detected by re-hashing, at $O(n)$ cost for full-chain verification.
- **Provenance verification.** Verifying one memory's provenance costs $i$ hashes on a linear spine ($5 \times 10^{8}$ for mid-chain in the assumed workload) or $30$ hash checks with a Merkle index at $960$ bytes of overhead per commit.
- **Cross-link storage.** $k = 4$ links per commit gives $4 \times 10^{6}$ edges and $256$ MB of address-and-label storage at the assumed 64 bytes per edge.
- **Capacity positioning.** The ultrametric strand is not bound by the Hopfield loading limit $\alpha \gtrsim 0.138$ [7] because it does not retrieve by energy descent; it instead pays a factor-2 node overhead. Dense associative memories with super-linear capacity [2] remain the better choice when patterns must be completed from heavily corrupted cues; the BMR is the better choice when provenance and order must be guaranteed alongside recall.

## 6. Discussion

The BMR's claim is that similarity, order, and provenance are facets of one composite object, and the derivations support a narrow version of that claim: the composite admits efficient retrieval ($4.17 \times 10^{4}$ speedup under stated assumptions) and exact integrity ($4.3 \times 10^{-60}$ collision probability) simultaneously. The claim is narrow because every number rests on assumptions about workload shape, and because the composite inherits a distinct failure mode from each strand.

*Limitations list.* The result rests on the following assumptions, with sensitivity:

1. **Balanced tree (A1).** If the tree is skewed, descent cost rises to the maximum depth $L_{\max}$; a pathological chain-like tree makes descent $O(N)$ and erases the speedup entirely. Rebalancing a hash-chained spine is nontrivial because content addresses fix the history — this is an open problem, not a solved one.
2. **Exact cue-to-centroid comparison (A2).** Noisy comparisons at internal nodes send descent to the wrong subtree, and unlike energy-descent attractors there is no basin to recover; a single wrong turn at the root loses half the memory. Sensitivity is maximal at shallow levels: one error at level 1 doubles the search space and can exclude the target altogether.
3. **Cross-link filter yield (A3).** The headline cost of 24 comparisons assumes the filter cuts 64 candidates to 4; if the filter yields nothing relevant, cost rises to 84 (speedup $1.19 \times 10^{4}$), and if cues are ambiguous the filter may drop the correct candidate — a precision failure the cost model does not capture.
4. **Random-oracle hashing (A4).** The birthday bound assumes ideal hash behavior; structured inputs could correlate, though 256-bit widths make exploitation infeasible in any known scenario.
5. **Workload scale (A5).** $N = 10^{6}$ and $n = 10^{9}$ are assumed, not observed; for $N = 10^{3}$ the speedup is only $10^{3}/24 \approx 42$, and the engineering overhead (Merkle indexing, tree maintenance) may not pay for itself at small scale.
6. **No error correction.** The BMR gives up the attractor-basin error correction that energy-based associative memories provide [10] and that oscillatory models refine under active noise [7]; a corrupted cue is handled by exhaustive cluster scan, not by relaxation.
7. **Flat-energy inheritance.** Any hybrid that adds an energy-descent stage to the BMR inherits the dead-neuron pathology: large flat regions of the energy function where sensitivity and stability fail [11], and the caveat that a Lyapunov function guarantees neither existence of steady states nor absence of limit cycles [11].
8. **Thermodynamic trade.** If a dense-associative completion stage is added for corrupted cues, the result of [8] applies: higher-order completion must run at lower temperature, with greater entropy production, to avoid relaxing to metastable configurations.

*What would falsify the main result.* The central claim is that composite retrieval is efficient and integrity-preserving simultaneously. It would be falsified by a construction or workload analysis showing that the three strands cannot be maintained consistently under updates — specifically, if inserting a commit into the ultrametric tree requires rehashing or readdressing a super-constant number of existing commits, the factor-2 storage overhead and $O(L)$ descent would not survive dynamic workloads, and the "one object" claim collapses into three loosely coupled indexes. A single demonstrated update protocol with super-constant readdressing per insertion refutes the result; conversely, an $O(L)$ insertion protocol confirms it.

*Open questions.* How forks and merges interact with ultrametric geometry (a merged commit has two parents and therefore two tree positions — does it get two leaves, and at what deduplication cost?) is unresolved. Whether the temporal spine can be physically instantiated as a phase-ordered oscillator chain, in the spirit of the synchronization-based encoding of [4] and the active-noise robustness of [7], is speculative. The relationship between the BMR's sparse cross-links and the dense outer-product relational memory of [6] — sparsity trades recall of unlinked relations for storage — is unquantified here. And the biological claim that astrocytic machinery stores memory [3] suggests, but does not demonstrate, that braided storage has a neural substrate.

## 7. Practical Implications and Engineering Pathways

**(a) Who would use the result and what changes.** The immediate users are engineers building retrieval-augmented and agentic AI systems, and the auditors and compliance officers who oversee them. If the result holds, the design parameter that changes is the memory layer's data model: instead of a vector index plus a separate log plus a separate audit store, a single content-addressed commit DAG with ultrametric indexing replaces all three, and the policy that changes is conflict handling — divergent recollections become visible forks rather than silent overwrites. Provenance verification becomes a property checked per query (30 hash checks with Merkle indexing, per Derivation 4) rather than a periodic audit.

**(b) Current readiness.** This work is purely analytical and has not been peer reviewed; against the NASA Technology Readiness Level definitions it sits at TRL 1–2: basic principles defined and a concept formulated, with analytical derivations but no experimental proof of concept. It does not exceed TRL 3, and no claim of implementation or manufacturing readiness is made.

**(c) Smallest next test.** The smallest de-risking calculation is an insertion-cost analysis: specify a concrete protocol for inserting a commit into the ultrametric tree of a hash-chained spine and prove (or refute) that it readdresses $O(L)$ existing commits. This is a paper-and-pencil exercise on the definitions of Section 3; the outcome that refutes the main result is a proof that insertion forces super-constant readdressing. The smallest experimental step beyond that would be a software prototype benchmarking recall accuracy, conflict resolution, and provenance verification of the quipu-net architecture (ultrametric vector store plus hashed commit DAG with cross-references) against vector-database and RAG baselines on a fixed corpus; the measurement that would falsify the retrieval claim is a recall-precision curve showing the cross-link filter discarding the correct candidate more often than the baseline retrieves it.

**(d) Binding constraints.** The first constraint to bind is the update-path problem from Section 6: content addressing freezes history, so any rebalancing of the ultrametric tree must be expressible as new commits rather than in-place edits, and the storage cost of that append-only discipline is not derived here — an open question. Second, cue-noise robustness: without an attractor stage, retrieval precision depends entirely on embedding quality at internal tree nodes, and no embedding model is evaluated here — open. Third, storage growth: the spine is append-only by design, so lifetime storage grows monotonically with $n = 10^{9}$
